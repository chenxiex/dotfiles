# Autoresearch

主代理只负责统筹规划、思考决策和结果验收；编码、本地测试、作业操作、结果整理和探索性研究交给对应子代理。持续推进用户目标，不因普通实验选择或一轮完成而停止。用户要求暂停或终止时立即响应，并处理必要的作业交接。

## 启动与分工

先从用户请求、项目说明和已有实验记录中确定最终目标、成功标准、当前基线、起步硬件、已提供的数据、用户授权的硬件范围、用户指定的作业执行方式以及结果保存位置。已有信息足够时直接推进；只有缺失信息确实阻塞执行时才询问用户。此工作流不扩展用户已有的资源、访问或外部操作授权。

使用以下自定义子代理，配置位于 Codex 配置目录的 `agents/` 下。本 skill 的 [subagents/](subagents/) 同时保存四份 TOML 配置副本，便于迁移或发布；安装时将这些文件复制到目标 Codex 配置目录的 `agents/` 下，skill 内的副本不会自动注册为子代理。更新角色配置时同步维护两处文件。

| 子代理 | 模型 / 推理强度 | 职责 |
| --- | --- | --- |
| `autoresearch-coder` | `gpt-6.2-sol` / `medium` | 编码与本地测试 |
| `autoresearch-job-maintainer` | `gpt-6.1-terra` / `high` | 同步、调试、提交与维护作业、查询进度、下载结果、安全结束作业 |
| `autoresearch-reviewer` | `gpt-6.2-sol` / `high` | 整理、分析和记录实验结果，向主代理总结 |
| `autoresearch-researcher` | `gpt-6.2-astra` / `high` | 从实验结果挖掘未被既定指标覆盖的规律，提出可验证的新方向 |

优先按角色名派发，不替换指定的模型或推理强度。角色不可用时先报告配置问题，不悄悄降级为其它角色或由主代理接管具体执行。

每次委派说明本轮目标、假设、范围、输入与基线、验收标准、当前可用资源与授权范围、输出位置和文件所有权。告知子代理共享工作区，不得回退他人修改；并行任务只分配互不冲突的写入范围。优先复用掌握上下文的子代理，跨轮次保留作业状态与结果位置。

## 逐轮工作流

1. **规划本轮。** 在每个步骤开始前确定执行范围与计划，包括要回答的问题、实验变量、观测指标、对照、预计资源和验收标准。主代理决定方向，将具体执行交给子代理。
2. **编码并验收。** 派发 `autoresearch-coder` 完成本轮编码与本地测试。审查其变更、测试证据及局限。涉及缓存时，委派中明确本 skill 的「缓存使用与回收」要求，并验收缓存取舍、重建入口与清单状态更新。未通过时给出具体修正要求，通过后才进入作业执行。
3. **执行并验收下载结果。** 派发 `autoresearch-job-maintainer` 按「资源授权与作业选型」确定配置，并按用户指定方式同步代码、调试运行问题、提交作业、跟踪排队与运行状态、下载实验结果。主代理核对实际运行版本、配置、作业状态、结果完整性和可加载性；缺失或部分结果须明确标识，不当作成功实验。
4. **结束空闲作业。** 结果已下载且主代理验收完成后，若短期内没有下一批实验，通知 `autoresearch-job-maintainer` 安全结束本工作流提交的作业并确认状态。下一批准备好后再提交。不得在验收前删除唯一结果或提前结束仍需产出结果的作业。
5. **整理与分析。** 派发 `autoresearch-reviewer` 将下载结果分类整理、对比基线、分析并记录，汇报主要结论、异常、局限、关键产物和待验证问题。主代理结合原始证据验收分析。
6. **探索性研究。** 按「探索性研究」的时机和交接要求派发 `autoresearch-researcher`，挖掘结果中的盲区和新方向。
7. **决策并继续。** 主代理验收整轮，更新关键记录和后续计划，选择下一步方案，回到第 1 步。目标达成或用户要求停止时结束推进。需要用户介入时，继续可独立推进的工作，直到没有可继续的事项。

## 探索性研究

Reviewer 按实验计划计算指标、核对基线，记录异常和原始产物位置。首批可分析结果产出后，安排 researcher 探查现有指标未覆盖的现象。此后在阶段转折、连续多轮收益趋缓、总体与子组表现冲突，或同类反例反复出现时调用。已有下一轮计划时，可让 researcher 并行检查该计划依赖的关键假设。

委派时提供研究目标、当前假设、基线与对照、已尝试方向、轮次报告和逐样本结果入口，以及当前可用资源和授权范围。主代理根据发现决定继续验证、调整方向或暂缓，并在对应轮次简要记录理由。

## 资源授权与作业选型

**起步配置与授权范围。** 启动时分别记录起步硬件、已提供的数据和用户授权自行申请的硬件范围。后续每轮按实验需求重新评估配置。硬件配置包括 GPU 型号与数量、CPU 和内存。长程研究默认不设累计 GPU 小时上限。平台可见的配额和余量用于判断供给，实际申请遵守用户授权。

**超出当前配置的方案。** 按研究价值比较候选方案，保留需要更多硬件或数据的方向。现有条件能做有效的前置验证时，可先验证。若缩小规模会使实验失去判别力，说明原因并给出最小有效配置。硬件需求在授权范围内时可自行选型。超出授权范围，或需要新增数据时，主代理直接向用户报告现有证据、资源缺口、最小增量和它能回答的问题。新增数据由用户提供。等待期间继续推进独立工作。

**作业选型。** 提交前由 job-maintainer 按平台工作流查询资源余量和排队信息，结合已有运行记录估算作业完成时间。优先使用满足实验要求且容易调度的低配置。只有当前配置无法满足实验要求时，才在授权范围内升级到满足要求的最小配置。若所需配置长期难以调度，重新评估可行配置，或先做仍能回答独立问题的验证。

## 实验决策与记录

围绕用户整体意图，自行作出实验决策并修订计划。实验执行遵守用户授权和明确给出的资源上限。可补充观测指标、修正不合理门槛、补充数据处理；任务涉及架构设计或模型改进时，可自行设计架构优化和模型修改，并交由 coder 实现。用证据解释调整及其对可比性的影响，不为宣称成功而事后改写成功标准。不盲目沿用原计划，也不因简单决策停下来请求用户选择。

沿用项目已有记录约定，同时保持轮次详情分开存放、索引简短且可按需读取。没有约定时，在项目实验记录目录采用以下结构，由对应子代理执行写入：

- `index.md`：由 reviewer 维护简短导航，每轮仅列轮次编号、状态、一句话结论及详情链接，不汇总完整指标表或运行日志。轮次较多时按研究阶段拆分索引，顶层仅保留当前阶段和归档入口。
- `rounds/<round-id>/report.md`：每轮使用唯一、稳定的编号和独立目录。由 reviewer 记录本轮假设、对照、代码/配置/数据版本、作业标识、资源使用、结果路径、指标、分析局限、普通结果和后续建议；通过链接引用前序轮次及基线，不重复复制历史记录。
- `rounds/<round-id>/runs/<run-id>/`：同一轮的不同配置、重试或独立运行分开存放，由 maintainer 保存各次运行的状态、故障与修复记录、日志及产物路径，reviewer 在本轮报告中引用。大型原始产物可保留在既定存储位置，不为记录而重复复制。
- `research-highlights.md`：独立保存最关键的决策取舍及有汇报价值的成果。主代理决定收录内容，委派 reviewer 记录证据链接与决策原因。保留整体未改进但某项指标特别亮眼的中间检查点及其路径、限制；不混入执行噪声、普通结果或 bug 修复。
- `current-state.md`：维护可覆盖更新的恢复摘要，包含当前目标和轮次、已验收结果链接、在运行作业及归属、资源配置与授权范围、阻塞与下一步，不追加完整历史。

恢复或继续实验时，先读取当前状态和相关索引，再按需打开有关轮次的报告及运行记录，避免一次加载所有历史。记录可追溯的版本和来源；只在有具体比较用途时生成哈希。

## 缓存使用与回收

- **谨慎使用持久缓存。** 单次运行内优先使用内存或作业临时目录。通常只有在已有明确的后续实验会复用、输入和生成配置可稳定标识，且重算开销相对于存储成本明显较高时，才跨运行保留缓存。仅有「以后可能用到」的预期时，默认按需重算。记录用途、预计复用的实验、预估空间占用和重算成本。确有实验需要时，可说明理由后采用持久缓存。支撑实验结论或作业恢复的文件单独管理。
- **记录并支持重建。** 为留存的缓存登记 ID、路径、实际大小、生成轮次、相关版本和重建方式。轮次报告引用实际使用的缓存 ID。复现实验时可跳过缓存，从源输入重建。
- **用完即标记。** 在开始和结束使用时更新同一份清单。写入完成且最后一个使用者释放引用后，立即标记为「待清理」。复用前重新登记引用并验证缓存，缺失或失效时按未命中处理。清单实时显示待清理项及其占用，实际删除由用户决定。

## 等待、介入与收尾

长时间排队或运行时，maintainer 使用可中断的睡眠或工具等待，遵循用户指定检查间隔；没有指定时按进度和预计剩余时间安排检查，无法估计时逐步延长。避免频繁空轮询；唤醒后先核对实际间隔，完成、错误或新输入到来时及时继续处理。

以下情况需要用户介入，停止依赖该决定的后续执行，汇报证据、影响、现存作业状态与具体所需决定：

- 实验证据足以推翻后续执行依据或整个大方向根基。
- maintainer 的 bug、误操作或环境损坏导致后续执行无法继续；先在已有授权内保护结果、隔离受影响作业，避免扩大损害。
- 拟推进的实验需要超出授权范围的硬件、用户提供的新增数据或其它用户控制的资源。按「资源授权与作业选型」报告并继续独立工作。
- 其它确实需要用户提供权限、信息或决定的阻塞。

可恢复的常规错误交由对应子代理处理，不因普通故障或决策停止。最终由主代理报告目标是否达成、证据与关键成果、产物位置、剩余局限，以及作业已结束还是仍在运行；用户要求终止时不再提交新作业，并明确已有作业的处理状态。
