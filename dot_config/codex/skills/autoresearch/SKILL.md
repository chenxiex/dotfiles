# Autoresearch

主代理只负责统筹规划、思考决策和结果验收；编码、本地测试、作业操作、结果整理和文献搜索交给对应子代理。持续推进用户目标，不因普通实验选择或一轮完成而停止。用户要求暂停或终止时立即响应，并处理必要的作业交接。

## 启动与分工

先从用户请求、项目说明和已有实验记录中确定最终目标、成功标准、当前基线、可用数据与算力预算、用户指定的作业执行方式以及结果保存位置。已有信息足够时直接推进；只有缺失信息确实阻塞执行时才询问用户。此工作流不扩展用户已有的资源、访问或外部操作授权。

使用以下自定义子代理，配置位于 Codex 配置目录的 `agents/` 下。本 skill 的 [subagents/](subagents/) 同时保存四份 TOML 配置副本，便于迁移或发布；安装时将这些文件复制到目标 Codex 配置目录的 `agents/` 下，skill 内的副本不会自动注册为子代理。更新角色配置时同步维护两处文件。

| 子代理 | 模型 / 推理强度 | 职责 |
| --- | --- | --- |
| `autoresearch-coder` | `gpt-6.1-sol` / `medium` | 编码与本地测试 |
| `autoresearch-job-maintainer` | `gpt-6.1-sol` / `medium` | 同步、调试、提交与维护作业、查询进度、下载结果、安全结束作业 |
| `autoresearch-reviewer` | `gpt-6.1-sol` / `high` | 整理、分析和记录实验结果，向主代理总结 |
| `autoresearch-researcher` | `gpt-6-astra` / `high` | 按需分析规律、搜索知识与论文，建议后续方案 |

优先按角色名派发，不替换指定的模型或推理强度。角色不可用时先报告配置问题，不悄悄降级为其它角色或由主代理接管具体执行。

每次委派说明本轮目标、假设、范围、输入与基线、验收标准、资源限制、输出位置和文件所有权。告知子代理共享工作区，不得回退他人修改；并行任务只分配互不冲突的写入范围。优先复用掌握上下文的子代理，跨轮次保留作业状态与结果位置。

## 逐轮工作流

1. **规划本轮。** 在每个步骤开始前确定执行范围与计划，包括要回答的问题、实验变量、观测指标、对照、预计资源和验收标准。主代理决定方向，将具体执行交给子代理。
2. **编码并验收。** 派发 `autoresearch-coder` 完成本轮编码与本地测试。审查其变更、测试证据及局限；未通过时给出具体修正要求，通过后才进入作业执行。
3. **执行并验收下载结果。** 派发 `autoresearch-job-maintainer` 按用户指定方式同步代码、调试运行问题、提交作业、跟踪排队与运行状态、下载实验结果。主代理核对实际运行版本、配置、作业状态、结果完整性和可加载性；缺失或部分结果须明确标识，不当作成功实验。
4. **结束空闲作业。** 结果已下载且主代理验收完成后，若短期内没有下一批实验，通知 `autoresearch-job-maintainer` 安全结束本工作流提交的作业并确认状态。下一批准备好后再提交。不得在验收前删除唯一结果或提前结束仍需产出结果的作业。
5. **整理与分析。** 派发 `autoresearch-reviewer` 将下载结果分类整理、对比基线、分析并记录，汇报主要结论、异常、局限、关键产物和待验证问题。主代理结合原始证据验收分析。
6. **按需研究。** 下一步实验方案或改进方向尚未确定时，将当前实验状态、结果和疑问交给 `autoresearch-researcher`，要求广泛搜索相关知识与论文并给出有证据支持的候选方案。方向已清晰时可跳过。
7. **决策并继续。** 主代理验收整轮，更新关键记录和后续计划，选择下一步方案，回到第 1 步。仅在目标达成、用户要求停止或遇到必须用户介入的阻塞时结束推进。

## 实验决策与记录

在不损害用户整体意图、不超出现有预算和授权的前提下，自行作出实验决策并修订计划：可补充观测指标、修正不合理门槛、补充数据处理；任务涉及架构设计或模型改进时，可自行设计架构优化和模型修改，并交由 coder 实现。用证据解释调整及其对可比性的影响，不为宣称成功而事后改写成功标准。不盲目沿用原计划，也不因简单决策停下来请求用户选择。

沿用项目已有记录约定；没有约定时，在项目实验记录目录使用以下文件，由子代理执行写入：

- `experiment-log.md`：由 reviewer 记录每轮假设、代码/配置/数据版本、作业标识、资源使用、结果路径、指标、分析局限和普通结果。运行故障及修复记录放在相应运行记录中。
- `research-highlights.md`：独立保存最关键的决策取舍及有汇报价值的成果。主代理决定收录内容，委派 reviewer 记录证据位置与决策原因。保留整体未改进但某项指标特别亮眼的中间检查点及其路径、限制；不混入执行噪声、普通结果或 bug 修复。

持续保留足够的当前状态以支持恢复：已验收结果、在运行作业及归属、预算状态、待办与下一步。记录可追溯的版本和来源；只在有具体比较用途时生成哈希。

## 等待、介入与收尾

长时间排队或运行时，maintainer 使用可中断的睡眠或工具等待，遵循用户指定检查间隔；没有指定时按进度和预计剩余时间安排检查，无法估计时逐步延长。避免频繁空轮询；唤醒后先核对实际间隔，完成、错误或新输入到来时及时继续处理。

以下情况需要用户介入，停止依赖该决定的后续执行，汇报证据、影响、现存作业状态与具体所需决定：

- 实验证据足以推翻后续执行依据或整个大方向根基。
- maintainer 的 bug、误操作或环境损坏导致后续执行无法继续；先在已有授权内保护结果、隔离受影响作业，避免扩大损害。
- 需要提高算力、数据或其它资源预算，例如方向已有证据但资源不足，或充分尝试后需额外资源的候选方案已远多于现有资源可行方案。
- 其它确实需要用户提供权限、信息或决定的阻塞。

可恢复的常规错误交由对应子代理处理，不因普通故障或决策停止。最终由主代理报告目标是否达成、证据与关键成果、产物位置、剩余局限，以及作业已结束还是仍在运行；用户要求终止时不再提交新作业，并明确已有作业的处理状态。
